# 헬스장 로봇 GUI

지름 10cm 원형 디스플레이(1080×1080)용 인터랙티브 화면.
파일 하나(`index.html`)로 끝나고, 빌드도 의존성도 없다.

- 배포 : https://dab2n.github.io/baton-gym/
- 실기기(키오스크) : 위 주소 뒤에 `#screen` — 목업 하우징·토글·카메라 썸네일이 빠지고 스크린이 화면을 꽉 채운다
- 병원 로봇 : https://github.com/dab2n/baton — 디자인 시스템(스크린 비율·베젤·배경 레이어·모션·카메라 스펙)을 그대로 공유한다

## 조작

| 입력 | 동작 |
|---|---|
| 얼굴이 ≈30cm 안으로 | 구슬이 화면을 채우며 첫 문장 |
| 엄지척 | 다음 단계로 진행 (이후 자동 재생) |
| 화면 탭 / Space / Enter | 한 장면씩 수동 진행, 마지막에서 처음으로 |

카메라나 권한이 없으면 인식만 조용히 꺼지고 탭 조작이 남는다.

## 크기

지름 10cm 는 병원 로봇(7인치 · 177.55mm)의 0.56배라, 같은 물리 크기로 읽히려면
1080 좌표계 안의 활자를 1.78배로 키워야 한다. 그래서 본문 42→76px, 부가정보 30→52px,
칩 20/14→36/26px 로 올렸고 화면당 문장은 한 호흡으로 줄였다.

장면은 `index.html` 의 `SCENES` 배열 하나로만 관리한다. 문구·머무는 시간·칩 노출을
거기서 고치면 되고, CSS 는 건드릴 필요가 없다.

## 텍스트 컬러

엄지척 **이전**(장면 2)은 `mix-blend-mode:normal` — 투명감 없이 단색.
**이후**는 `color-burn` — 뒤의 파란 블롭이 흘러 지나갈 때마다 글자 색이 미묘하게 바뀐다.

## 인식 값 보정

웹캠 화각마다 다르므로 실기기에서 `index.html` 하단 세 값만 만진다.

```js
const NEAR = .34;   // 얼굴 폭 ÷ 프레임 폭. 화각 65° 기준 0.34 ≈ 30cm, 0.5 ≈ 20cm
const HITS = 3;     // 트리거까지 필요한 누적 프레임
const GMIN = .35;   // 엄지척으로 인정할 최소 점수
```

## 디자인 시스템 (2026-09-12)

병원 로봇(dab2n/baton)의 바뀐 시스템을 그대로 옮겼다.

- 스크린 밖 여백 `#0B0F18`, 스크린은 검정에 위는 감청 아래 끝은 밝은 회색 띠.
  띠는 스크린과 같은 중심의 **동심원**으로 번지고(직선 경계가 가로줄로 보여서) 위/아래는 긴 마스크로만 나눈다.
  그 색은 `.rimlight` 가 18s 에 한 바퀴 돌아 가장자리를 따라 일렁인다
- 베젤은 그리지 않고 카메라 노치만 매끈한 반구(`ellipse cx 540 cy -10 rx 86 ry 88`), 기본값은 목업 없는 실화면
- 글자는 흰색 (줄 박스 66% 까지 순백 → 아래 끝만 알파 .55), 자간 0.03em, 강조어는 흰색 + `#FEFFF9` 글리밍 한 겹
  (글리밍 번짐은 `blur` 를 em 단위로 : 헬스장 글자는 76px 이라 px 고정이면 번짐이 너무 작다)
- 구슬은 어두운 화면에 맞춰 : `fill` 은 opacity .045 + grayscale, `search` 는 .06, 문구 장면(`full`)에선 감춘다.
  색 블롭(sheen·core·cyan)과 회전 발광은 idle 외에는 끄거나 크게 낮췄다
- **알약 모양 기기 칩 삭제** (CSS·마크업·장면 플래그 모두)
- 폰트 : Delight 가 없는 컴퓨터에선 `pretendard/` 서브셋으로 대체 (SIL OFL, 굵기별 자간 보정)
- 카드 디자인이 아직 없어 문구는 그대로 둔다

## 문장 등장 (2026-09-15, 병원 로봇과 동일)

- 문장 단위로 왼쪽부터 한 글자씩 : `letters()` 가 단어(.w) 안의 글자를 인라인 `.c` 로 쪼개 시작 시각 `--t` 를 준다.
  한 줄 안에서는 30ms 간격으로 끊김 없이, 문장 끝 +450ms (한 호흡 문장 hold1 은 쉬지 않음), 숫자 → 문장 → 보조 문구 사이 +380ms
- 가장 최근에 나타난 글자에 유리·비눗방울 색 번짐 (`letterIn`) : 일반 글자는 옅게(알파 ×.35), 강조어는 짙게
- 강조어는 켜진 뒤에도 번짐이 글자를 따라 일렁이고(`emGlow`), 글리밍 겹은 첫 글자 시각에 시작해 마지막 글자까지 훑는다
- 색·그라디언트는 글자(.c)에 입힌다 : 단어에 입히면 아직 안 켜진 글자까지 그려 단어가 통째로 먼저 보인다
- 번짐·흐림 크기는 em 단위 (글자가 52 ~ 240px 로 제각각)
- 숫자(카운트)는 병원 로봇 길안내와 같은 **5x7 도트** 로 직접 그린다 (`drawCount`). 칸마다 원을 깔고 켜진 칸만 불을 켠다
- 카운트업은 자리 이동 없이 칸마다 불이 꺼지고 켜지며 이전 숫자에서 한 칸씩(110ms) 올라간다 (0→1→2→3, 5→6→…→10).
  자릿수는 총 횟수(/10) 기준으로 미리 잡아 3/10 과 10/10 의 "/" 가 같은 자리 : 세트 내내 숫자가 옮겨 다니지 않는다
- 흐림은 약하게 : 등장 흐림 .05em, 강조어 일렁임은 가장자리만 (.012~.04em / .03~.1em), 글리밍 겹 .025 / .05em
